# Vietnamese Vibe — правила проекта

Веб-приложение для изучения вьетнамского с нуля: карточки фраз по темам (тоны, транскрипция, перевод, озвучка) и «Практика» — микро-диалоги с ИИ-носителем языка. Интерфейс и все тексты для пользователя — на русском.

Сайт: https://vietnamese-vibe-app-d9rf.vercel.app · Репозиторий: https://github.com/zuzuka-duduka/vietnamese-vibe-app

## Стек

- **React 19 + Vite 8**, чистый JavaScript (JSX), ES-модули (`"type": "module"`)
- **Tailwind CSS 4** через `@tailwindcss/vite`; дизайн-токены в `src/index.css` (`@theme`)
- **Supabase** — таблица `vietnamese_words`, чтение из браузера через anon-ключ + RLS
- **Gemini API** (OpenAI-совместимый endpoint, бесплатный тариф) через серверную функцию **Vercel `/api/chat`**; OpenRouter — запасной провайдер
- **Web Speech API** (`speechSynthesis`, `vi-VN`) — озвучка
- **Vercel** — хостинг; деплой автоматически при `git push` в `main`

## Команды

```bash
npm install
npm run dev      # http://localhost:5173, /api/chat обслуживает middleware из vite.config.js
npm run build    # обязательно перед каждым коммитом
```

Тестов нет. Чистую логику (`src/lib/*`, `src/data/*`) проверяем короткими node-скриптами (`node script.mjs`), UI — в браузере.

## Архитектура

```
api/chat.js                Vercel Function: GET — статус ИИ, POST — реплика ИИ → server/chat.js
server/chat.js             ЕДИНСТВЕННОЕ место, где живут ключи ИИ, системный промпт и вызов провайдера
vite.config.js             dev-middleware /api/chat → тот же server/chat.js
src/App.jsx                вкладки «Карточки» / «Практика», загрузка слов
src/components/
  CategoryBrowser.jsx      master-detail: сетка категорий → карточки категории
  VietnameseCard.jsx       карточка фразы
  DialoguePractice.jsx     чат «Практики»
  ToneText.jsx             раскраска тонов + подсветка обращений
  SpeakButton.jsx          кнопка озвучки 🔊
  AgePronounNote.jsx       пометка «обращение зависит от возраста»
  Notice.jsx               плашки-предупреждения
src/lib/
  tones.js                 6 тонов и определение тона по диакритике (NFD)
  pronouns.js              возрастные обращения (anh, chị, em, bạn…) и исключения
  dialogue.js              системный промпт, MAX_AI_TURNS, разбор JSON-ответа ИИ
  ai.js                    клиент /api/chat (ключей здесь нет и быть не должно)
  supabase.js              клиент Supabase
  speech.js                озвучка
src/data/
  categories.js            словарь категорий (название, иконка) + fallback 📌
  situations.js            ситуации «Практики»
  phrases.js               демо-данные, пока Supabase не настроен
src/hooks/                 useVietnameseWords, useVietnameseVoice
supabase_schema.sql        схема, RLS и начальные фразы (идемпотентный)
supabase_add_translations.sql  миграция данных
```

Правила:

- **Код, общий для Vercel и dev-сервера, — только в `server/`.** `api/chat.js` — тонкая обёртка. Обработчик принимает стандартный `Request` и `env`, возвращает `Response`.
- **Промпт собирает сервер.** Клиент отправляет только `{ situationId, history }`; никогда не передаём с клиента системный промпт или произвольные `messages`.
- `server/` может импортировать из `src/lib` и `src/data` только чистые модули без `import.meta.env`, `window` и React.
- Новые ситуации «Практики» — в `src/data/situations.js` (их `id` проверяет сервер).
- Новые категории — в `CATEGORY_DICTIONARY` в `src/data/categories.js`; неизвестные категории из базы показываются автоматически с 📌 и отформатированным именем.
- Состояние — локальное в React (`useState`/хуки), без внешних стейт-менеджеров и роутера, пока не появится реальная потребность.

## Безопасность

- **В `VITE_*` — только публичные значения.** Vite встраивает их в JS сайта. Ключи ИИ — только без префикса (`GEMINI_API_KEY`, `OPENROUTER_API_KEY`) и читаются только в `server/`.
- После изменений, затрагивающих ключи, проверяем сборку: значений секретов не должно быть в `dist/assets/*.js`.
- **`.env.local` никогда не коммитим** (в `.gitignore`). Шаблон переменных — `.env.example`, он должен соответствовать коду.
- Не выводить значения ключей в логи, ответы API, сообщения об ошибках и чат — только имена переменных и признак «задан / не задан».
- **Supabase:** anon-ключ публичный, данные защищает RLS — для анонимов только `select`. Запись в базу — только через SQL Editor владельцем проекта. Не ослаблять политики и не добавлять в клиент `service_role`-ключ.
- **`/api/chat` валидирует вход:** известная ситуация, история чередуется assistant/user, не больше `MAX_AI_TURNS` реплик ИИ, реплика пользователя ≤ 300 символов, ИИ ≤ 2000. Ослаблять проверки нельзя — иначе функцию можно использовать как бесплатный чат-бот на наш ключ.
- Ошибки провайдера отдаём клиенту понятным русским текстом, без внутренних деталей.
- Ограничения по частоте запросов пока нет — при росте трафика добавить rate limit.

## Переменные окружения

| Переменная | Где | Описание |
|---|---|---|
| `VITE_SUPABASE_URL` | браузер | Project URL Supabase |
| `VITE_SUPABASE_ANON_KEY` | браузер | anon / publishable key |
| `GEMINI_API_KEY` | сервер | ключ Google AI Studio |
| `AI_PROVIDER` | сервер | `gemini` (по умолчанию) или `openrouter` |
| `GEMINI_MODEL` | сервер | по умолчанию `gemini-3.5-flash`, запасная — `gemini-3.1-flash-lite` |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | сервер | только при `AI_PROVIDER=openrouter` |

На Vercel — Settings → Environment Variables; после изменения нужен Redeploy (`VITE_*` встраиваются при сборке).

## Данные (`vietnamese_words`)

- `pattern_sentence` — формат **«вьетнамское предложение — русский перевод»**, разделитель ` — ` (длинное тире с пробелами). Карточка делит по первому тире; без перевода показывает «Перевод пока не добавлен».
- `tone_type` — название тона с диакритикой: `ngang`, `huyền`, `sắc`, `hỏi`, `ngã`, `nặng`. Проверять по реальной диакритике ключевого слога (например, `lấy` — sắc, не ngã).
- `phonetic` — кириллическая транскрипция в квадратных скобках: `[чо той ка фе]`.
- `category` — ключ в `snake_case` из `CATEGORY_DICTIONARY`; `coffee` показывается внутри `food`.
- `word_vi` уникален. SQL-скрипты пишем идемпотентно: `create … if not exists`, `on conflict (word_vi) do nothing`, `update … where` с точным условием.
- Вьетнамский текст — всегда с полной диакритикой. Переводы, в которых есть сомнения, помечаем для проверки человеком.

## ИИ-собеседник

- Ответ модели — строго JSON `{"vi","phonetic","ru","tip","done"}`; разбор в `parseReply` (`src/lib/dialogue.js`) устойчив к ```-обёрткам и мусору вокруг.
- Диалог — до `MAX_AI_TURNS` (4) реплик ИИ; номер реплики сообщает сервер служебной пометкой, на последней ИИ ставит `done: true` и даёт `tip` («Кстати, лучше сказать так: …»).
- «Размышления» модели — на минимуме (`reasoning_effort: 'low'` для Gemini, `reasoning.effort: 'minimal'` для OpenRouter), иначе лимит токенов уходит на них и ответ приходит пустым.
- При 429/500/503 сервер сам пробует запасную модель. `finish_reason: length` и пустой ответ — ошибка, а не пустой пузырь.
- Модели Gemini быстро устаревают и меняют поддерживаемые параметры — при ошибках 400/404 сверяться с https://ai.google.dev/gemini-api/docs/openai и /pricing.

## Стандарты UI и кода

- Весь пользовательский текст — по-русски; вьетнамский текст оборачиваем в `lang="vi"`.
- Цвета — только токены из `src/index.css` (`paper`, `ink`, `muted`, `line`, `accent`, `tone-*`); не хардкодить hex в компонентах (кроме служебных amber/red для плашек).
- Вьетнамские фразы показываем через `ToneSyllable`/`ToneText`: тон каждого слога + подсветка возрастных обращений. Рядом с фразой — `SpeakButton`.
- Возрастные обращения (anh, chị, em, cô, chú, bác, ông, bà, cháu, bạn, mình) всегда помечаются (`AgePronounNote`) — новичок не должен заучивать их как часть фразы. Новые ложные срабатывания добавлять в исключения `src/lib/pronouns.js` (bác sĩ, chú ý, tiếng Anh, bạn bè…).
- Каждое состояние загрузки видно пользователю: загрузка, ошибка с понятным текстом, пустой список, «не настроено» с инструкцией.
- Вёрстка адаптивная (от 375px), без горизонтальной прокрутки.
- Стиль кода как в существующих файлах: функциональные компоненты, без точек с запятой, одинарные кавычки, 2 пробела, короткие комментарии на русском — объясняют «почему», а не «что».
- Не писать `\u…`-экранирование кириллицы/диакритики в исходниках — используем сами символы (UTF-8 без BOM).

## Рабочий процесс

1. Изменения → `npm run build` без ошибок → проверка в браузере (`npm run dev`).
2. Коммит с понятным сообщением на русском.
3. `git push` в `main` → Vercel пересобирает сайт (~30 с) → проверить опубликованную версию.
4. Изменения данных — SQL-скрипт в корне репозитория; выполняет владелец в Supabase SQL Editor.

## Известные особенности окружения (Windows)

- Терминал, открытый до установки Node.js, не видит `npm` — открыть новый.
- Dev-сервер иногда перестаёт замечать изменения файлов на диске D: — перезапустить `npm run dev`.
- В встроенном браузере Claude нет вьетнамского голоса — реальное звучание проверять в Chrome/Edge.
